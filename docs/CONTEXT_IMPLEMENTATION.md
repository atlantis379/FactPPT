## 已实现

1. 总结审核合同升级为`summary_review.v2`。普通提纲及结构化提纲的每条`key_points`都有绑定整个总结版本的目标ID；原有`point_coverage`、核心句和关系仍分别审核。缺项、多项、重复ID、旧版本、非法结论、自审和无问题说明的非完整支持结论均拒绝。关键要点的问题进入原有阻断/驳回机制，确认稿展示其审查意见。
2. worker领取新增可关闭的`--input-format shared-v1`。原任务合同、业务输入哈希和租约文件保留；另存`.model.json`及`.context_metrics.json`。模型包包含完整实际证据，完全相同的长字符串只出现一次，来源身份不合并。包哈希和原始输入哈希分别核对，可以完整还原。缺失引用、内容改动或保留键冲突拒绝处理。
3. `fetch-assets`在本地文件哈希与当前合同完全一致时跳过下载；有差异则重新下载并验实际字节。没有重新生成工具资产或复用检查结论。
   主线worker的`queue/complete/asset/fail`默认请求简短回执，避免每次操作再次输出完整来源和历史任务；`--full-response`恢复原响应。服务API的原默认完整响应和旧流程行为保持兼容，续约原本已经只返回租约期限。
4. 独立同章实验入口`tools/chapter_draft_benchmark.py`冻结来源与输入，记录真实响应和结构失败，逐页存档，可恢复已存档调用；原文审核复用生产验收器，实验快照只写实验目录，不提交现网任务或确认。云端模型通过独立Codex执行端实测，本地模型通过串行HTTP执行。

## 使用

```powershell
.\.venv\Scripts\python.exe tools\codex_worker.py claim FLOW_ID --kind SUMMARY_REVIEW --worker REVIEWER --out data\worker\task.json --input-format shared-v1
.\.venv\Scripts\python.exe tools\codex_worker.py complete FLOW_ID --task data\worker\task.json --result data\worker\result.json --compact
```

模型读`.model.json`，每个`$shared_text`在同包的`shared_texts`解析为完整原字符串，按未改变的业务结果合同输出。提交仍使用原`task.json`，不要把模型包当租约或用传输哈希替代业务版本。默认`original`仍保持原传输行为。不能把SECOND_READ改用作者答案或初读缓存；首版只开放SUMMARY和SUMMARY_REVIEW的共享格式。

实验入口：`prepare`冻结整章逐页包；`local`运行本地首稿；`synthesize`形成本地章级综合；`prepare-review`从候选创建匿名审核合同；`validate-review`调用原应用验收器验证逐项审核覆盖。实验不是已确认课件，不授予本地模型正式审核资格。

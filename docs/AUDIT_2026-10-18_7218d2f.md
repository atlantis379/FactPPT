## 0. 一句话结论

**这是一套"机制层"做得相当扎实、而"证据层"尚未闭环的医疗内容系统。**
内容哈希、事务、租约、失效传播、导出完整性这些工程骨架是真的、可验证的；但凡是"某人说他已经看过/已经检查过/就是这句话"的地方，几乎全部由提交方自我声明，程序没有真正的独立校验。而产品对外承诺的正是最后这一层。

因此，当前版本**在受控内部试用中可用，在"内容可审计"的对外承诺上不能签字**。三个必须先修的点：①事实库"逐字"判定存在可伪造关键数字的漏洞；②审核独立性只是字符串比较；③A 路线视觉资产回执完全自证。

| 级别 | 数量 | 含义 |
|---|---|---|
| Critical | 4 | 直接击穿产品的核心承诺，可产生"程序核对通过"的错误结论 |
| High | 10 | 可导致错误交付、数据丢失、未授权访问 |
| Medium | 12 | 削弱保证、性能/并发缺陷、可复现性问题 |
| Low | 8 | 卫生、可维护性、误导性文档 |

## 2. Critical（必须修，否则核心承诺不成立）

### C-1 事实库"逐字"判定可被空白折叠伪造关键数字 **[实测]**

`factdeck/lexicon.py:26-32` 的 `canon()` 删除**所有**空白；`factdeck/facts.py:152` 用 `canon(quote) in canon(unit_text)` 判定逐字。

复现（`tmp/_verify2.py`）：

```
单元原文: 剂量分 5 10 20 三档
提交引文: "510"          显示: "510"
→ status=ACCEPTED  problems=[]      ← 三个并列剂量被折叠成一个不存在的数字 510
```

同样地，`quote = "本品1 0mg每日一次"` 对原文 `本品10mg每日一次` 也判为 ACCEPTED。

**为什么这是 Critical**：这是本产品唯一的"数字不可伪造"保证。`critical_tokens` 事后比较的是 `510` vs `510`，因此**后续所有数字核对都会同意**。幻灯片会印出一个来源中不存在的剂量，且审计链完整、回执齐全。
**建议**：照抄 `claims.page_claims`（`factdeck/claims.py:90-92`）的做法——宽松定位、然后用原文切片**替换**引文（`quote = unit_text[at[0]:at[1]]`）；并拒绝跨越"数字之间的空白"的 `canon` 匹配。

### C-2 派生（derivation）通道是自证的，可以不引用任何真实证据 **[实测]**

`factdeck/facts.py:175-196`：只要 `f_ders` 非空就放行，`derivations` 的 `problems`（证据事实缺失）**只记录、从不拒绝**；`app/deckflow.py:2796-2807` 的 `confirm_derivation` 只校验"决定 + 审核人姓名非空"。

复现（`tmp/_verify_claims.py`）：

```
事实: quote="起始剂量5mg"  display="本品每日一次20mg"  derivation="d1"
推导 d1: evidence=["f900"]（该事实不存在），已由"人工"确认
→ fact.status=ACCEPTED  needs_confirmation=False
   fact.problems=['显示文字经推导得到：按说明书惯例换算']
   derivation.problems=['证据事实缺失或未通过：f900']   ← 被忽略
```

另可让推导引用**它自己要改写的那条事实**（`evidence=["f1"]`）并同样通过。

**为什么这是 Critical**：所有"非逐字"内容唯一的合法出口，是一个不校验证据的出口；等于给"逐字"承诺开了一扇其后没有门的窗。
**建议**：任一具名推导带 `problems` ⇒ 该事实 REJECTED；禁止事实出现在自己推导的 `evidence` 中；`confirm_derivation` 在 `d.problems` 非空时拒绝。

### C-4 A 路线视觉资产"回执校验"只验容器、不验内容 **[实测（子审计 probe2 + 我复读代码）]**

`app/deck_generation.py:513-552`：`asset_sha256` 是"上传文件自己的哈希"，`contract_sha256` 抄自合同，`tool` 只是白名单字符串，`tool_call_id` 只要求非空，`qa.inspected / text_free / semantic_graphics_removed / illustrations_kept` 全是提交方的布尔值。PNG 只检查格式、≥600×300、16:9±2%（`:544`），报错文案却写着"不能裁剪、拉伸或换用截图"。

子审计以真实 `Store.visual_asset` 复现：一张带文字的红底截图被接受为"设计稿"；**同一份字节**被接受为"去字稿"（`design.sha256 == clean.sha256`）；一份手写单路径 SVG 被接受为"Adobe 矢量化结果"；一张绿色纯色图被接受为下一页的设计稿。

更直接的一处：**`tools/codex_worker.py:66` 写着 `qa = {"inspected": True}`** —— 仓库自带的执行端 CLI 无条件声明"已查看实际输出"，而服务端正是靠这个字段判断"须查看实际输出后提交检查记录"（`deck_generation.py:534`）。这与 `AGENTS.md`"Do not claim inspection you did not do"直接冲突。

**影响**：Route A 的整个视觉层在程序意义上没有证据。配合 `factdeck/visual_render.py:240-243`（只用 `layout.model` 与 vector SVG，design/clean 两张 PNG **从不进入 PPT**），意味着"生成设计稿 → 去字 → 矢量化"这条流程对最终交付物的影响**不可验证**。
**建议**：至少 ①同一页 `design` 与 `clean` 的 sha 必须不同且像素差在阈值内；②`clean` 必须由 `design` 派生（记录派生关系并校验像素相关性）；③SVG 必须含最小路径数/顶点数下限并与 design 的连通域数量级一致；④删除 `qa={"inspected": True}`，改为必填且回执中记录可供复核的检查证据。

## 3. High

### H-1 HTTP 层完全无认证，且接受任意 `Host` 头 → DNS rebinding **[实测]**
`app/main.py:2985-2990` 只有 `FastAPI(...)` + 两个 router + `/web` 静态挂载，**全仓 0 个 `add_middleware`**：没有 `CORSMiddleware`、没有 `TrustedHostMiddleware`、任何路由都没有 `Depends` 或 token 校验。`start.ps1:17` 绑定 `127.0.0.1` 正确，但这不能阻止 rebinding（浏览器把 `Host: evil.example:8001` 发到本机）。实测 `Host: evil.example:8001` 请求 `/api/projects` → 200 + 项目列表。
**建议**：`TrustedHostMiddleware(["127.0.0.1","localhost"])` + 安装时生成 per-install bearer token 由 `start.ps1` 注入。

### H-2 无 CSRF 防护，且多个"GET"在改状态 **[实测]**
无 Origin/`Sec-Fetch-Site` 校验；`app/main.py:3123-3129`（`GET /policy/{action}` 会写审计并 `save_projects`）、`:4637`/`:4696-4702`（`GET .../presentation.pptx` 会生成文件并改状态）、`app/deckflow_api.py:477-481,569-572`（无 body 的 POST 都是 CORS-simple 请求，可被任意网页跨站触发）。实测带 `Origin: https://evil.example` 的表单 POST 成功推进了流程并新增审计事件。
**建议**：Origin/Referer + `Sec-Fetch-Site` 校验；把改状态的 GET 全部改成 POST。

### H-3 `data/projects.json` 无锁读改写 + 非原子写 → 静默丢更新、截断后全站 500 **[实测]**
`app/main.py:858-870`：`load_projects()` 读整个文件，`save_projects()` 用 `STORE.write_text(...)` 原地截断重写。FastAPI 把同步 `def` 端点放在线程池并发执行，所以真实的并发交错会发生。实测：两个重叠写入 → 一次更新**丢失**；写入中途被打断 → 文件只剩 13 字节，`json.loads` 抛错，此后**所有** `/api/*` 请求 500，且无备份。因为每次写都会重写 `audit_chain`，一个丢失更新在事后与"篡改"无法区分。
这正违反 `AGENTS.md`：*"do not replace them with concurrent writes to `data/projects.json`"*。
**建议**：legacy 层迁到 `Store.transaction`；短期至少文件锁 + 临时文件 + `os.replace` + 保留上一版。

### H-4 上传无长度上限，且在项目校验**之前**落盘 **[实测]**
`app/main.py:3204` `content = await file.read()`（无 `MAX_UPLOAD` 限制，对比 `app/deckflow_api.py:238` 的正确写法）；`:3212` `target.write_bytes(content)` 之后 `:3213` 才 `get_project(project_id)`。实测：POST 到不存在的项目 → 返回 404，但 `.docx` 已写进 `data/`；41 MB 内容在接受 40 MB 拒绝之前已被完整读入内存。
**建议**：有界读取、先校验项目、目录配额、全局 body 上限。

### H-5 解压放大（zip bomb）：120 KiB 的 `.docx` → 265 MiB 堆 **[实测]**
`app/source_extract.py:15-17,58` 只限制**压缩后**字节（40 MiB），`:132-140` 按成员整体 `archive.read()`；`factdeck/ingest.py:489/381/552` 的 `Document()`/`Presentation()`/`load_workbook()` 先解压，单元/文本上限（`:33-35`）在 `:608` 才生效。实测 120.3 KiB 上传 → `word/document.xml` 展开 120 MiB（1021×）、堆峰值 265 MiB，且拒绝发生在膨胀**之后**；通过 HTTP 300 ms 内可达。
**建议**：解析前用 `ZipFile.infolist()` 校验解压后总大小；在受限子进程（内存 + 超时）里解析。

### H-6 作者文字守卫被同一类黑名单化问题击穿 **[实测]**
`factdeck/lexicon.py:129-154`，`factdeck/deck.py:411-412`：

| 页面标题 | 完整 `deck.check` 结果 |
|---|---|
| `格列美脲单药方案` | **0 错误** |
| `他汀类药物比较` | **0 错误** |
| `疗效卓越` | **0 错误** |
| `半数患者可获益` | **0 错误** |
| `血压↑` | **0 错误** |
| `阿司匹林` | **0 错误** |

根因之一明确：`:148` 的正则 `r"[一-鿿]{1,6}" + suffix` 要求药物后缀**前面至少有一个汉字**，所以药物名出现在字符串开头（标题最常见的位置）时不匹配 —— 实测 `格列美脲` → `[]`，`使用格列美脲` → 命中。
**建议**：把方向反过来（作者文字 = 词表 + 结构词，其余一律要求逐页人工签核）；至少修掉正则前置断言、补中文数量词/箭头/实体字典（用事实库 `entity` 派生）。

### H-7 术语表（glossary）可以洗白数字 **[实测]**
`factdeck/deck.py:383-394` + `factdeck/lexicon.py:138-140`：lint 前会把 glossary 词从文本中删除。实测同一标题 `12项研究支持该结论`：
- 无 glossary → 1 个错误（`作者文字含关键项：12项`）
- 加 `glossary=[{"text":"12","fact":"f1"}]` → **0 错误**

且术语只需"出现在某条已通过事实的引文中"，不需要是术语。
**建议**：拒绝 `critical_tokens(term)` 非空的 glossary 项或带药物后缀的项。

### H-8 `hero.value` / `statement` 可以是作者散文 **[实测]**
`factdeck/deck.py:35-39`：`hero` 只要求 `title` + `value`，`value={"text":"半数患者可获益"}` + 页内任意一条事实 → **0 错误**。`LAYOUT_GUIDE`（`:70`）示范的是 `{"value": fact}`，但没有代码强制。这是"实质内容只能来自事实库"最直接的一个缺口：整页主视觉数字/结论可以完全由模型撰写。
**建议**：`hero.value/label`、`statement.statement`、`chart` 条目标签强制 `{"fact":…}`，作者文字只允许出现在 `title`。

### H-9 语义审查者自选严重度，CONTENT_ERROR 标成 NOTE 即不阻断 **[实测（读码 + 子审计驱动）]**
`app/review_ledger.py:161-162`（`sev = x.get("severity")`，只校验取值合法）、`:86-97`（`blocking()` 只取 `severity == "BLOCKER"`）。子审计实测：一条"数值缺失：原文 12 mmHg，页面未显示"以 NOTE 提交 → `blocking()=[]`、`awaiting_human()=[]`，只在 `to_acknowledge()` 里，流程继续。

**建议**：按 `category` 在代码里定级（`CONTENT_ERROR`/`EVIDENCE_MISSING` ⇒ BLOCKER）；降级必须有人工裁定记录。

### H-10 审核独立性 = 未认证字符串的不等比较 **[实测（读码 + 子审计）]**

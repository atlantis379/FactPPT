# 原件图片引用

状态：第一期（原件内嵌图片）已实现，2026-09-28；第二期（PDF 区域截取）未开始。设计中许可粒度、清晰度阈值、去标识确认已由用户确定。取代“插画生成”，后者不计划做（见 `IMPLEMENTATION_STATUS.md`）。

## 目标

让原始资料里的图（机制示意图、KM 曲线、森林图、流程图、影像、照片）作为**有来源的内容**上页，
与事实库同一套原则：

1. **像素只来自原件，由代码取出。** 执行端只能指出“哪一张图”或“哪一块区域”，不产生、不修改像素。
2. **图不能自己说话。** 页面上关于图的任何说法（“A 组优于 B 组”“中位生存期 …”）仍须是文字事实的逐字引文；
   执行端对图的描述只用于审核，不上页。
3. **图中的文字和数字要转录。** 沿用现有图表转录与第二次独立转录，图上看得到的字都能被核对。
4. **截取要完整。** 图例、坐标轴、脚注、显著性标记、样本量表、“非头对头比较”之类说明不能被裁掉，需人工对照原件确认。
5. **逐张图登记使用许可。** 客户逐张确认图可以复用，页面上标注来源。
6. **不泄露患者信息。** 每张上页图都要有人确认已去标识。

## 数据模型

### 图（figure）——资料的一部分，导入或阅读时产生

```json
{
  "id": "S03:p4:g1",                 // {page_id}:g{n}
  "source_id": "S03", "page_id": "S03:p4",
  "location": "第4页 图2",
  "method": "embedded",              // embedded：原件内嵌图片；page_crop：页面区域截取
  "bbox": [0.08, 0.31, 0.92, 0.78],  // page_crop 时必填，页面归一化坐标 [x0,y0,x1,y1]
  "path": "…/figures/<sha>.png",     // 不可变文件，与资料原件同样按校验值存放
  "sha256": "…", "width": 1800, "height": 1100,
  "caption_unit_ids": ["S03:p4"],    // 图题/图注所在的文字单元（可为空）
  "transcription_unit_ids": ["S03:p4:x.g1c1", "…"],   // 图中文字的转录单元
  "reader": "reader-1",
  "note": "KM 曲线，两组，含风险人数表"   // 执行端描述，仅供审核，不可引用
}
```

- `embedded`：由代码在导入时抽取。PDF 用 pypdf 的 `page.images`；PPTX 取图片形状的原始数据；DOCX 取内嵌图片；
  单独导入的图片文件本身就是一张图。过小的图（图标、logo、装饰线，默认短边 < 120px）不登记。
- `page_crop`：矢量图表、多张小图拼成的图等无法按内嵌图片取出的，由阅读执行端给出 `bbox`，
  代码把该页渲染为位图（PDF 用 pypdfium2，200 dpi）后按 `bbox` 截取。截取结果的校验值写入记录。
- 图文件与资料原件一样不可变；资料变更或移除时，图随之失效。

### 图事实（figure fact）——事实库中的一条

```json
{"id": "fig.km", "figure": "S03:p4:g1", "section_ids": ["s3"], "caption": ["km.cap"], "note": ""}
```

- 没有 `quote`/`display`；`caption` 是本图随附的文字事实（通常是原件图题的逐字引文），可为空。
- 核对规则（加在 `facts.verify`）：
  - `figure` 必须存在、校验值与存档一致；
  - 图中若有文字（`transcription_unit_ids` 非空），这些转录单元须已通过第二次独立转录或人工确认，否则 `needs_confirmation`；
  - 截取完整性须经人工确认（见下），否则 `needs_confirmation`；
  - 该图未登记使用许可或未确认去标识时，图事实为 `needs_confirmation`（草稿可渲染，正式渲染被拦）；
    许可为不允许、或去标识结论为“含可识别信息”时，图事实为 `REJECTED`。
- 冲突检测不涉及图事实。

## 流程改动

| 环节 | 改动 |
|---|---|
| 导入 | 代码抽取内嵌图片，登记为 `embedded` 图，页面继续标 `requires_visual`。 |
| READ_SOURCE | 阅读结果每页增加 `figures`：确认或忽略代码登记的图，补充 `page_crop` 区域；每张图给出图中文字的逐格转录（沿用 `transcription`，单元以 `g{n}c{m}` 编号并挂到图上）和审核用描述 `note`。 |
| SECOND_READ | 图中文字的转录单元与现有转录一样由另一执行端盲读。另加一项：对每张 `page_crop` 图独立给出 `bbox`，与第一次的交并比 < 0.9 时转人工确认。 |
| SUMMARY | 不变；总结可以提到“第4页图2 显示的研究设计”，但总结本身不上页。 |
| FACTS | 可提交图事实。任务说明增加规则：关于图的说法只能引用资料文字；不得根据图读数、推算或描述趋势。 |
| DECK | 新版式 `figure`，并允许 `compare` 的面板放一张图（见下）。 |
| 人工确认 | 每张上页图新增两项：**截取与去标识确认**（审核人对照原页确认没有裁掉图例、坐标轴、脚注、标记，并确认图中无患者可识别信息）；**使用许可**（客户逐张登记，见下）。 |
| SEMANTIC_REVIEW | 任务说明带上图片地址和原页地址，要求审核人看图，检查页面文字是否说出了图外的结论、并列两张图是否暗示原文没有的比较。 |
| 渲染 | 见下。 |
| 交付 | `verification_report.json` 列出每张上页图：来源位置、方式、校验值、截取与去标识确认人、许可记录。 |

### 使用许可（逐张图）

客户对每张上页图登记一次，绑定图的校验值：

```json
{"figure_id": "S03:p4:g1", "figure_sha256": "…", "permitted": true, "scope": "本项目内部培训",
 "customer": "…", "operator": "…", "method": "…", "at": "…", "identity_assurance": "LOCAL_RECORDED_NOT_AUTHENTICATED"}
```

- 只有页面规格里用到的图才进入待确认清单；未用到的图不需要登记。
- 图的校验值变化（重新截取、资料替换）后原登记失效。
- 界面提供“本资料中全部上页图”一次勾选多张的便利，但落库仍是逐张记录。
- 页面上的来源标注由代码生成，不由执行端书写。

### 截取与去标识确认（逐张图）

审核人对照原页登记，绑定图的校验值：

```json
{"figure_id": "S03:p4:g1", "figure_sha256": "…", "crop_complete": true,
 "deidentified": "NO_PATIENT_CONTENT" | "DEIDENTIFIED" | "IDENTIFIABLE",
 "reviewer": "…", "note": "…", "at": "…", "identity_assurance": "LOCAL_RECORDED_NOT_AUTHENTICATED"}
```

- `crop_complete` 必须为 true 才算确认；发现裁掉内容时不登记，改为重新截取。
- `deidentified`：图中没有患者相关内容（示意图、曲线）选 `NO_PATIENT_CONTENT`；影像、病理、照片等已确认无姓名、
  住院号、日期、面部、可识别体征等选 `DEIDENTIFIED`；含可识别信息选 `IDENTIFIABLE`，该图被拒绝，不能上页。
- 程序不做图像去标识处理，也不遮挡、打码（那会修改原件像素）；含可识别信息的图只能换图或由客户提供已去标识的原件。
- 执行端阅读时可在 `note` 中提示“可能含患者信息”，界面据此醒目标出，但结论只能由人登记。

## 页面规格

```json
{"id": "km", "layout": "figure", "title": {"text": "生存曲线"},
 "figure": {"fact": "fig.km"},
 "side": [{"fact": "km.median"}, {"fact": "km.hr"}],
 "outline_ids": ["outline_3"], "section_ids": ["s3"]}
```

- `figure` 版式：一张图 + 0–3 条侧栏事实；图占主要区域。
- `compare` 面板可以用 `{"figure": {"fact": …}}` 代替条目列表，至多两张图并排。
- 图上不允许叠加箭头、高亮、圈注或文字（改变图的含义，程序无法核对）。需要强调时用侧栏文字事实。
- 规格检查：图事实必须是图事实（反之亦然）；一页至多两张图；图事实的 `caption` 自动作为图下说明渲染。

## 渲染

- HTML 中图为 `<img data-figure="fig.km">`，`object-fit: contain`，保持原始宽高比，不裁切；
  图下由代码生成两行：图题（`caption` 事实，逐字）和来源（`文件名 · 位置`，系统文字）。
- 清晰度：按显示尺寸计算有效分辨率，低于 150 dpi 记为警告（不拦截），提示放大版面或以更高 dpi 重新截取；逐页审核时由审核人判断是否可读。
- PPTX：用**存档的原图文件**插入图片（不用截图），位置取自预览页；来源行与图题是原生文本框。
- 回读核对新增：每张图在 PPTX 中存在，图片数据的校验值与存档一致，宽高比偏差 < 1%，不越界、不被遮挡。
- 页面备注的来源追溯中列出图的来源位置与截取方式。
- `render_input` 纳入图的校验值、截取与去标识确认、许可记录；任一变化使渲染失效。

## 界面

- 资料页：每份资料的图以缩略图列出（方式、位置、是否有转录、截取、去标识与许可状态；可能含患者信息的图醒目标出）。
- 人工确认页：使用许可逐张登记（可按资料批量勾选）；截取与去标识确认显示“原页整页 + 截取框 + 截取结果”并排，勾选“已对照原件确认截取完整”并选择去标识结论后提交。
- 渲染审核不变：逐页审核时图与文字一起看。

## 分期

1. **第一期（已实现）**：`embedded` 图（PDF、PPTX、DOCX、图片文件）；图事实与核对；`figure` 版式；渲染、PPTX 插图与回读；
   截取与去标识确认（对 `embedded` 截取即确认“图就是原件那张、完整无缺”）与逐张使用许可；界面。
2. **第二期**：PDF `page_crop`（pypdfium2 渲染 + 执行端 bbox + 第二次独立 bbox）；`compare` 面板放图。
   pypdfium2 目前只是 pdfplumber 的间接依赖，届时需在 `requirements.txt` 中显式列出。
3. **不做 / 替代方案**：PPTX 原生图表与 SmartArt 无法直接取出图片，也不引入 LibreOffice 渲染；请客户提供该 PPTX 导出的 PDF，
   作为同一资料的另一份原件导入后按 `page_crop` 截取。

## 第一期实现说明

- 代码：`factdeck/ingest.py`（取图）、`factdeck/facts.py`（图事实核对）、`factdeck/deck.py`（`figure` 版式与图位检查）、
  `factdeck/render.py` + `extract.js` + 模板（排版、PPTX 插入原图、回读）、`app/deckflow.py` / `deckflow_api.py`（阅读、确认、许可、渲染绑定、交付清单）、
  `web/deck/app.js`（资料页图片、事实库缩略图、人工确认表单）。测试：`tests/test_figures.py`。
- 接口：`GET …/figures/{图编号}/file`；`POST …/confirmations/figures/{图编号}/review`（审核人、`crop_complete`、`deidentified`）；
  `POST …/confirmations/figures/{图编号}/licence`（客户、操作人、方式、`permitted`、范围）。
- 与设计的差异：`compare` 面板放图属于第二期；PPTX 中的原生图表/SmartArt 仍只能靠客户提供导出的 PDF。
- 只在测试中用生成的线框图验证过，尚未用真实资料里的图跑过。

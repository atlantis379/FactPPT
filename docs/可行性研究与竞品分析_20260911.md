## 0. 结论先行

**判定：技术上可行、方向上正确、当前形态下商业化不成立，但存在一条高价值的窄切口。**

三句话概括：

1. **你做的不是"AI 生成 PPT"，而是"证据 → 幻灯片的可审计中间层"。** 这个中间层在市场上**确实是空的**——通用 AI PPT 工具（Gamma、Kimi、WPS AI）没有溯源，学术引用类工具（ChatSlide、EvidenceMD、Tosea）有引用但没有机器可验证的审计链，企业合规平台（Veeva PromoMats、Vodori、Workiva）有审计链但不生成语义级幻灯片内容。**没有人在"语义命题级溯源 + 强度控制 + 失效传播"这一层做产品。**
2. **项目最大的资产不是代码，是那套规则体系。** 150+ 条冻结规则、四级锁、来源忠实与临床正确分离、`value_origin` 数值来源分级、标题强度不得超越 Claim——这些是**行业公认痛点，但全行业目前只靠人工清单在管**（见竞品 24Slides、pharmatools.ai 的做法）。这是真正的差异化。
3. **项目最大的风险也不是技术，而是"自证"。** 文档自己写了"Self-check is insufficient"、"生成与验证上下文逻辑隔离"，但**没有任何机制实现它**；同时系统没有哈希链/签名，AuditLog 只是数据库字段，无法防事后篡改。结果是：**它现在无法向任何第三方证明自己声称的可审计性。** GOLD 2026 审计拿到 `PARTIAL_WITH_BLOCKERS`（Q-SEM / Q-LOGIC 双双 FAIL），恰好就是这个问题的一次实盘暴露。

**如果只做三件事，做这三件：** ① 给交付快照加密码学溯源锚（哈希链 + C2PA 兼容清单 + 中国《标识办法》要求的元数据字段）；② 把验证模型与生成模型彻底分离，并改为"回读渲染后 PPTX 实物"的接地反思；③ 把 GOLD 2026 审计做成公开可复现的基准（含负样本），用标准换话语权。

## 1. 项目还原：它到底是个什么东西

### 1.1 定位（原文口径）

> "把复杂医学材料转化为**可讲、可核验、可追溯、可审阅**的专业演示内容，而不是把 PDF 自动套进漂亮模板。"

> "系统不承诺 'AI 100% 医学正确'。"

这句话是产品灵魂，也是市场定位的关键：**卖的是"可核验性"，不是"正确性"。** 这个区分很重要，因为它决定了买家是谁（见 §4.2）。

### 1.2 核心链路

```
PDF 上传 → Source Extractor → Triage → Architect → Verifier
        → Compliance → Visual Router → Approved Semantic Page Graph
        → 原生 PPTX 打包 → 逐页 QA → Medical Review Sheet → 不可变交付快照
```

架构铁律一条：**"任何模型不得直接跨越 Source → Final Deck"**。

### 1.3 真正稀有的五个机制

| 机制 | 具体内容 | 为什么稀有 |
|---|---|---|
| **Claim 原子化 + 永久绑定** | 每条 Claim 同时保存 `source_quote` 与 `normalized_claim`；`SOURCE / SUMMARY / SYNTHESIS` 三类 provenance 从 Claim 层开始记录 | 全行业没人做。ChatSlide 保留的是**引用编号**，不是命题级 provenance |
| **强度控制（Title Entailment）** | "标题和 Primary Message 的语义强度不得超过底层 Claim 能支持的最大语义强度"；禁止"相关→导致""可考虑→推荐""支持→证明" | 这是医学传播中最常见、也最致命的错误。目前**只有人工清单在防**（见 24Slides、UT Health 的 ACCME 检查表） |
| **数值来源分级** | `value_origin`：原文精确值 / 受控派生 / 图中估值 / 未报告；**"未报告不能替换为 0"，"图中估值不能标成精确绑定"** | pharmatools.ai 的实操文档里专门警告"AI 把 HR 0.73 四舍五入成 0.7 就是改变证据"——痛点真实存在，但市场上没有产品化方案 |
| **失效传播（Staleness）** | 上游语义改动 → 依赖图下游全部 STALE → 受影响 Gate 必须重跑；"不得使用动态 latest 引用作为最终审计依据" | 这是软件工程（Workiva 的 linked data）的做法，被移植到语义层。**AI PPT 赛道无人做** |
| **原生可编辑 PPTX + 语义连接线 ID** | 由 Artifact Tool 生成原生对象，连接线带精确 Relationship ID，页脚与 Speaker Notes 保留 `[Sources]` | 客观上正确的技术选择。24Slides 实测指出 Gamma/Tome 的"液态画布"**根本做不出药企要求的像素级精确版式**，且导出必损 |

### 1.4 实际实现程度（比文档自述的乐观）

代码基线文档说"尚不包含模型驱动抽取、真实医学审稿、图像生成或生产级任务队列"，容易让人以为只是个骨架。实际不是：

| 指标 | 实际情况 |
|---|---|
| 后端接口 | **51 个**（`app/main.py`，2908 行），覆盖 extract / triage / architect / verify / compliance / route-visuals / semantic-deck / pptx / delivery-manifests 全链路 |
| 打包与美化 | `native_beautifier.py` 546 行（5 种确定性版式 + 候选评分）、`packager.py` 345 行 |
| 端到端产物 | `output/` 下有 5 个真实 PPTX（含 GOLD 2026 四版迭代）、10 张逐页 PNG |
| 真实运行记录 | `runs/gold2026_copd_update_20260908/` 含证据、验证、叙事、视觉 QA 四阶段产物 |
| 外部审计 | 已产出 `audits/GOLD_2026_PPT_数据与逻辑审计.md`（哈希盖章、分维度结论） |
| 技能化封装 | `skills/auditable-medical-presentation-reference/` 已发布 v0.5.0 包 |

**结论：这是一个罕见地"跑得通、有真实产物、且被自己审计过"的原型。** 这在可行性判断中权重很高——绝大多数同类项目卡在"规则写了但没实现"。

**但落差同样明显：** LLM 尚未接入（只有 local deterministic adapter）、无任务队列、无数据库（未 freeze 技术选型）、无密码学溯源、规则总量已超出可维护阈值（Module04 60 条 / Module05 52 条 / Module06 41 条，且文档自己记录了跨 Batch 冲突与残留）。

| **C2PA Content Credentials** | 事实标准（500+ 成员 / 6000+ 关联方） | 签名 manifest 记录生成模型、版本、编辑链；新增 `c2pa.ai-disclosure` 断言；**Adobe、微软、Google、OpenAI、BBC、AP 已支持** |

## 3. 空白点分析：市场结构图

把"生成能力"和"可审计性"作为两个轴，格局非常清楚：

（见正文后的可视化图）

- **左上（强审计、不会生成）**：Veeva、Vodori、Lytho、Workiva、DataSnipper。它们管的是**文档与流程**，不是**语义命题**。
- **右下（强生成、弱审计）**：Gamma、Beautiful.ai、Copilot、Kimi、WPS AI、AiPPT。量大、便宜、免费。
- **右上偏下（有引用但不可验证）**：ChatSlide、Tosea、LayerProof、EvidenceMD。有 `[n]` 标记，但引用"存在"不等于"支持"——**这正是你文档里那句"SourceRef 存在不代表 Entailment 通过"**。这是你最好的一句攻击性文案。
- **右上顶（强生成 + 可验证审计）**：**空**。只有 EvidenceMD 靠"检索优先"逼近了一半（它保证了"引用真实存在"，但不保证"标题强度未越界"、不保证"未报告未被当成 0"、不保证"跨页隐含比较被拦截"）。

**所以空白点在右上角，而且空白的原因不是技术不可行，是没人愿意承担这套规则的维护成本。**

而这恰好也是**这条路的护城河**——规则体系难维护，所以先建立的人有先发优势；但同样难维护，所以也可能是自杀式的成本结构。§5 会给出取舍建议。

## 4. 可行性分析

### 4.1 技术可行性：**高（7/10）**

**支撑它的：**
- 核心链路已跑通，51 个接口、真实 PPTX 产物、真实审计报告。不是纸上架构。
- 原生可编辑 PPTX 是客观正确的技术选择。24Slides 的实测证明了"液态画布"和"模板注入器"在临床场景的失败模式，你避开了。
- 规则体系的可执行化程度高（`config/rules/mvp_rules.json` 有 14 条 HARD 规则，`generation_capabilities.json` 做能力资格化）。
- 学术路线已被验证可行且便宜：Paper2Poster 单张 $0.005；DeepPresenter-9B 逼近 GPT-5。

**卡住它的：**
- **LLM 尚未接入。** 抽取是规则型的，验证是确定性的。一旦引入 LLM，你文档里承认的三个问题会立刻变成现实问题：抽取召回、语义等价判定、自证偏差。
- **语义判定本质上是主观的。** "Minimum Sufficient Source Span"、"标题强度是否越界"、"两页之间是否形成隐含比较"——这些**无法确定性化**。你的设计把它交给 LLM + 人审是对的，但这意味着**吞吐量由人决定**，不是由机器决定。这是产品经济学的核心约束。
- **规则膨胀已失控。** 150+ 条规则、Module 间职责重叠、文档自记的跨 Batch 冲突。维护成本会随规则数超线性增长。
- **状态空间爆炸。** 11 个流程状态 × Issue 8 态 × 多套 status 枚举（`review_status` / `binding_status` / `compliance_status` / `qa_status`…）。这会导致实现难度和 UI 复杂度同时失控。
- **无密码学锚。** 这是当前最大的技术缺口，也是**最容易补的**（见 §6）。

**行业数据校准（重要）：** 2026 年头部模型在**摘要忠实度**上幻觉率约 1.0–2.5%，但在 **RAG 忠实度**上仍有 4–9%，在**长尾事实（含文献名/作者/日期）**上高达 10–25%，**近时事件** 30–60%。这意味着：**依赖"模型自己不要瞎编"是不可行的，必须依赖结构化约束 + 检索优先 + 机器校验。你的架构方向正确，但不要高估单一模型的可靠性。**

### 4.2 市场可行性：**中（5/10，但细分市场真实）**

**需求是真实的**，痛点有权威背书：
- pharmatools.ai 的操作清单明写：AI 会把 HR 0.73 舍成 0.7；有些 deck 10 页疗效 0 页安全性，过不了审。
- ACCME 指南要求披露 AI 使用并人工核验，责任在主办方——**这直接创造了"可证明已核验"的需求**。
- Veeva 数据：优化 MLR 流程可让审核周期缩短 57%；Vodori 客户报告 30–60% 缩短。**合规审核是药企公认的成本黑洞。**

**但需求≠可付费需求，问题在三处：**

| 客户群 | 付费能力 | 采购难度 | 判断 |
|---|---|---|---|
| 个人医生/医学生/规培 | 极低 | 低 | ✗ 会直接用免费的 Kimi/WPS，或被 $15/月的 ChatSlide 截胡 |
| 三甲医院科教科 / 学会 / CME 提供方 | 中 | 中 | **○ 最佳切入点**：有 ACCME 式披露义务、有预算、决策链短 |
| 药企医学事务（MSL/Medical Affairs） | 高 | **极高** | ◎ 天花板最高，但要过供应商审计、21 CFR Part 11、信息安全、BAA 类协议 |
| 医学内容制作方 / 学术服务商 | 中 | 低 | ○ 可做"能力输出"（卖审计报告/合规交付） |

**定价锚点（公开数据）：**
- 低端：ChatSlide $14.9–59.9/月；Tosea $14.99/月；国内 79–168 元/年（即触/AiPPT）
- 中端：Presentations.AI $198/年；Copilot $30/用户/月
- 高端（**这才是你的天花板参照**）：Workiva 平均 $59,653/年（区间 $36k–$155k，84 笔真实交易数据）；Veeva/Vodori 企业定制

**结论：按席位卖月费会死在低端红海里。必须按"交付物/项目/合规审计"计价。**

### 4.3 合规与法域可行性：**中高（7/10），且是顺风**

- **中国是顺风。**《标识办法》要求显式 + 隐式标识（元数据含 AIGC 符号、服务提供者编码、内容编号），而你的 AuditLog 字段设计已经覆盖了"生成属性 + 服务提供者 + 内容版本"。**你只需要把它写进文件元数据**，就完成了一项法定合规——这是竞品普遍没做的（国内 AI PPT 工具基本只做显式水印）。
- **海外是门槛。** EU AI Act 第 50 条 2026-08-02 生效（罚则 3% 营收），加州 SB 942 已生效。**要出海，C2PA manifest 是必要成本。** 好消息是 C2PA 已经成熟，实现成本不高。
- **法域风险要正视：** 设计文档**通篇未点名任何具体法规**（无《广告法》《生成式人工智能服务管理暂行办法》、GDPR、HIPAA 字样），但字段里出现了 `jurisdiction: "CN"`、`SourceQualification`、`RegulatoryVerification`。这是**有意为之的保守设计**（避免把法规写死），但也意味着**合规责任边界对外不清晰**，在药企采购中会被追问。建议补一份"适用法域与免责边界"的对外声明。
- **必须永久回避的红线：** 诊断、处方、无人工确认的临床决策支持。这已在非目标里，**坚持住**。

### 4.4 工程与成本可行性：**中低（4/10，最大风险项）**

- **规则治理成本是主要成本，不是模型成本。** 模型调用便宜（$0.005/海报级），但 150+ 条规则的定义、冲突消解、回归验证、文档同步，是**纯人力成本**，且随规则数超线性增长。文档里已经出现"Batch2 12 条 vs 13 条"残留与 C1/C2 冲突，这是预警信号。
- **重跑成本高。** 任一上游语义改动 → 依赖图级联失效 → 受影响 Gate 全跑 + targeted/regression 双重复验。这在"个人做一个 deck"的场景是不可接受的延迟；在"企业季度交付"的场景是可接受的。
- **人审是天然瓶颈。** 大量 `HUMAN_REVIEW_REQUIRED` / `AMBIGUOUS` 是**正常路径**而非异常。这让"减少医生审核时间"这个价值主张变得可疑——**你可能是把审核从"看 100 页"变成"看 30 项"，是效率提升，但不是自动化**。这必须诚实写进对外材料，否则客户会失望。

### 4.5 商业化可行性：**当前形态低（3/10），收敛后有中高**

问题：
- 没有付费客户证据、没有商业模式论述（PRD 完全没写定价/客户/竞品）。
- 目标用户跨度过大（医学生到药企），一个产品形态无法同时服务。
- "可审计"是**后台属性**，用户不会为它单独付费——**他们为"能过审/能交差/不出事"付费**。这是营销语境的根本差异。

机会：
- 有一条清晰的**从服务到产品**的路径：先做"可审计 PowerPoint 交付服务"（用 GOLD 案例当样例交付物），拿到 3–5 个真实客户，再产品化。
- 有一个**标准窗口**：P2P、Paper2Poster、PPTAgent 都在抢"评测标准"，但目前都是**生成质量**标准。**"可审计性/保真度验证"标准还没有人占位**。C2PA 定义了内容溯源标准，但没有定义"语义级溯源"标准。**这是你可以占的位置。**

## 6. 建议

### 6.1 定位收敛：选一条路，别横跨

| 路径 | 内容 | 优点 | 缺点 | 建议 |
|---|---|---|---|---|
| **A. 医学会议的"可审计交付层"** | 服务三甲科教科、学会、CME 提供方、医学内容制作方。按交付物计价 | 决策链短、有 ACCME/《标识办法》披露义务驱动、能快速拿真实客户 | 客单价中等、需人审服务能力 | **✓ 先做这个落地** |
| **B. 药企 MLR 前置语义校验层** | 不做全套，做"Veeva 之外的那一层"：语义强度、数值来源、跨页隐含比较的机器检查 | 天花板最高、价值最刚需 | 采购周期长、需 21 CFR Part 11 级资质 | **◎ 6–12 个月后作为天花板** |
| **C. 开源 + 标准** | 把 Claim/provenance schema、强度控制规则、GOLD 基准开源，抢"语义级溯源"标准位 | 建立护城河、获客成本低、学术背书 | 短期无收入 | **✓ 与 A 并行，用开源换话语权** |

**明确不做：** 通用 PDF→PPT 生成（红海且免费）、诊断/处方/临床决策支持（法域不可控）、自建文献检索引擎（EvidenceMD 已 40M+ 论文）。

### 6.2 立即要补的三项能力（按 ROI 排序）

**① 溯源锚：把"可审计"从声明变成可验证（1–2 周，最高杠杆）**

- 为 `Delivery Snapshot` 加**哈希链**：每个阶段产物的 `prev_hash + payload_hash`，形成不可篡改链。
- 输出 **C2PA 兼容 manifest**：记录生成模型/版本/时间/编辑链 + `c2pa.ai-disclosure` 断言。
- 写入**中国《标识办法》要求的隐式标识字段**：`AIGC` 标识符、服务提供者名称或编码、内容编号。
- 结果：**一次性同时满足国内法定要求 + 海外 AI 披露要求 + 我方审计链设计。** 这是全项目性价比最高的一步。

**② 独立验证 + 接地反思（2–4 周）**

- 验证模型必须**与生成模型不同厂商/不同权重**（学术已证明同源自证有系统偏差）。
- 验证输入改为**回读渲染后的 PPTX 实际对象**（读回文本框、形状、坐标、连接线 ID），而不是回读中间 JSON。这样能抓到"JSON 正确但渲染溢出/遮挡/顺序错乱"——**GOLD 审计里 A04（布局破坏阅读逻辑）正好是这类问题**。
- 建立 `SemanticDiff` 的**自动化**（文档已定义 SCOPE_EXPANSION / CAUSALITY_UPGRADE，但需要模型执行 + 规则兜底）。

**③ 把 GOLD 2026 审计做成公开基准（4–8 周）**

- 包含：正样本（合格的 deck）+ **负样本（已知错误的 deck，如删掉"例如"、把 1 次中重度写成通用路径、HR 四舍五入）**。
- 指标对齐学术界已有的语言（P2P 的细粒度 checklist、PPTEval 的三维），但**评测维度换成"可审计性"**：引用精度、引用召回、强度越界率、数值来源误标率、失效传播完整性。
- 结果：**你从"做产品的人"变成"定标准的人"。** 这是唯一能对冲大厂时间压力的手段。

### 6.3 产品上必须改的两件事

**① 把"RED 硬阻断"改为"分级降级交付"**
现在是硬 Gate：只要有一个 RED 未绑定就不可导出。结果是**交付率太低，客户会流失**。建议输出**页级置信标签**：允许交付，但每页带 `已核验 / 待人工确认 / 不可信` 标记 + 缺证据清单。**诚实标注不可信，比拒绝交付更有价值**——这也正是你"不伪装成原文事实"原则的正确落地方式。

**② 把来源块升级为"逐句可点回源 span"**
现在页脚是 `[Sources]` 块。而你已经有 `SourceSpanSupport` 数据结构了，只是没输出到 PPTX。改成：每句关键命题带可定位的 span 引用（页码 + 区间 + 原文片段）。这是**最容易做出、也最容易被客户感知**的差异点——EvidenceMD 只做到"来源列表"，ChatSlide 只做到"引文编号保留"，**没人做到"逐句回源"**。

### 6.4 商业化建议

1. **先卖服务，再卖软件。** 用 GOLD 2026 做样例交付物（含审计报告），去找 3 家三甲科教科 / 1 家医学内容制作公司 / 1 个学会。**拿到 3 个真实付费客户再谈产品化。**
2. **按交付物计价，不按席位。** 定价锚点：单份"可审计 deck + 审计报告"定价，对标人工审计服务成本，而非对标 $15/月的 SaaS。
3. **用"过审"语言，不用"可审计"语言。** 客户买的是"能过 MLR/能过 ACCME 披露/不被平台判疑似生成内容"，不是"你们有哈希链"。
4. **主动对接而非对抗。** Veeva PromoMats / EvidenceMD / ChatSlide 是潜在渠道与集成对象，不是取代目标。

### 6.5 建议的 90 天里程碑

| 时间 | 目标 | 验收判据 |
|---|---|---|
| 第 1–2 周 | 溯源锚落地 | 任一交付快照可被独立验证脚本验证哈希链完整；生成的 PPTX 元数据含 AIGC 隐式标识；C2PA manifest 可被公开校验器读取 |
| 第 3–6 周 | 独立验证 + 接地反思 | 验证模型与生成模型不同源；能自动检出 GOLD 审计中的 A02（删"例如"）、A03（运算符歧义）、A04（布局顺序）三类问题 |
| 第 7–10 周 | 公开基准 v0.1 | 发布含 10 正 + 10 负样本的可复现基准；给出可审计性 5 项指标基线 |
| 第 8–12 周 | 首批真实客户 | 3 份真实付费交付；每份附带机器生成的审计报告并被客户接受 |
| 持续 | 规则裁剪 | 规则总数不增而拦截率提升；每条规则有失败用例与误报率 |

## 7. 一页总结

**这个项目最有价值的洞察是：医学演示的问题从来不是"排版不好看"，而是"你无法证明你说的是原文说的"。**

全行业都在用人工清单解决它（24Slides 的人审、ACCME 的披露表、pharmatools 的 10 条 checklist、药企的 MLR 流程）。你把它做成了可执行的软件规则，并且已经跑出了一个真实产物、还自己审计出 `Q-SEM/Q-LOGIC FAIL`——**这份诚实的失败报告比任何 demo 都有说服力，它是你最好的售卖材料。**

**两件事决定成败：**
- **能不能把"可审计"变成密码学上可验证的**（哈希链 + C2PA + 隐式标识）——做不到，这句话永远是自说自话；
- **能不能把验证者与生成者真正分离**（跨厂商模型 + 回读渲染实物）——做不到，你拦不住 GOLD 审计里那类错误，而这恰恰是你唯一的产品价值。

**规模上要清醒：** 不要试图做通用 AI PPT（那个市场 2026 年约 19–33 亿美元但已被免费产品碾平），要做"证据到幻灯片的可审计层"——它没有独立的市场规模统计，**因为它还不存在，而这正是它可能是机会、也可能是伪需求的原因。** 用 90 天和 3 个付费客户来验证，比继续扩规则更值得。

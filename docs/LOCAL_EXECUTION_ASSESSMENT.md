# 本地代码与本地模型分工评估

**历史评估：** 2026-10-04用户已放弃本地模型接入。下文的模型迁移建议停止执行；当前只采用[Sol、Luna、本地代码三路径](THREE_PATH_EXECUTION_PLAN.md)。实验记录保留。

日期：2026-10-03。对象：FactDeck `/api/deck` 主线及已选定的 A 原生矢量路线。

后续补充：已使用用户提供的Bonsai27B完成23个本地推理小样本，实际结果见[LOCAL_MODEL_BENCHMARK.md](LOCAL_MODEL_BENCHMARK.md)。本文以下保留实测前的代码分工评估；其中“未实测”是该轮评估的时间状态，不代表后续仍未运行模型。

## 结论

项目适合采用「本地代码处理执行与校验、本地模型处理可验收的候选和草稿、云端处理高难度理解与视觉创作、人工完成现有确认」的分工。

第一优先级是减少 agent 执行程序性操作及重复上下文。更换模型之前就能做这些改进。将本地模型接入后，仍保留全文覆盖、原文追溯、独立复核及人工确认；本地模型输出不能自行成为事实或审批。

本次为代码与硬件评估，没有安装或测试本地模型，没有改变生产路由或项目确认状态。因此没有实测的模型吞吐、质量或费用节省比例。

| READ_SOURCE | 完整页清单、文字/图像输入、覆盖账本、结果格式检查 | 逐页分类、中文/英文 OCR、逐格转录候选 | 小字号、表格错列、符号、跨框关系等疑难页 | 可优先试本地视觉/OCR；不能用文本层提取代替实际看图 |
| SECOND_READ | 提供位置但隐藏首读答案、比对文字和截取框、输出差异清单 | 独立 OCR/视觉复读 | 未解决差异的原件核对及人工裁定 | 可用不同 OCR/模型独立运行；同一输出重复执行或改 worker 名不能证明独立 |

| SUMMARY | 全页/提纲覆盖、引用解析、数字/单位/否定词差异提示、重复证据去重 | 按章摘要初稿、教学组织草稿 | 范围歧义、条件组合、医学总结的独立审查 | 适合分章本地试运行；必须遍历全部来源，不能靠检索跳过未命中页 |

| DECK | 事实 ID、内容完整、布局容量、关系端点、几何、样式与来源检查 | 主题组织、选版式、拆页、设计说明草稿 | 难以压缩的语境、关系表达、整体设计判断 | 原生版式已有；本地草稿需按原有规则验收 |

## 已有本地实现与需要新增的能力

已经实现：

- `factdeck/ingest.py`：结构化文件拆解、PDF 文字层及备用分栏提取、渲染与截取。
- `factdeck/claims.py`：逐字跨度及类型/范围字段校验，数字、限定词和引用标记提取。
- `factdeck/facts.py`：逐字事实、显示节选及冲突检查。
- `factdeck/visual_layout.py`：布局结果只允许改几何/样式，不能替换医学文字或数据关系。
- `factdeck/native_vectors.py`：实际 SVG → 原生路径；不是位图 → SVG 的图像描摹器。
- `factdeck/visual_render.py`：浏览器容量/重叠检查、原生导出、PowerPoint 渲染与编辑能力检查。
- `tools/visual_worker_runtime.py`：90 秒续约及有时限的后台运行，可减少人工处理 15 分钟租约过期。尚无完整无人值守模型 worker。

需要新增：

- 适用于全部任务类型的本地 worker 调度器，复用原 SQLite 领取和 `claim/complete/fail/renew` 合同。
- 证据包去重、按页/章处理、按 ID 获取完整原文上下文，避免反复把项目历史送入模型。
- 本地 OCR/视觉与文本模型调用器、模型/版本/参数/输入哈希/耗时/内存记录，以及失败转现有执行端的机制。
- 本地模型资格基准及独立审查协议。模型来源和商业使用授权应在实际选型时核实；本报告没有选定模型。

## 先补的程序检查

`app/deckflow.py:1012` 的摘要审查验收，逐点强制覆盖的是 `section.point_coverage`。普通提纲的摘要主要使用 `key_points`，本次 67 条 key_points 在审查 brief 中有完整证据，但 result_contract 中没有相应的逐条必填判定槽。

这意味着当前独立执行端可以主动逐项审查，但程序不能以合同强制保证所有普通提纲关键要点都被判断。`points` 是结构化提纲要点槽；关系另在 `relations` 字段。这不是本地模型能解决的问题，应由代码为 key_points 提供稳定 ID、完整判定槽与对应验收，同时保持旧结构化提纲及历史结果兼容。

## 本机适合承担的试运行

优先试：文本层抽取、文件与规则校验；单实例本地 OCR；小型量化文本模型按页/章生成 CLAIMS 或 SUMMARY 草稿。OCR、视觉模型和文本模型按阶段串行加载，PPT 导出另用 CPU/Office 队列。

8 GB 显存及约16 GB系统内存会限制长上下文、视觉分辨率和并行数。某个量化模型能否运行还取决于权重、上下文缓存、视觉编码器、运行库和其他进程；不能仅凭参数规模宣称可用。当前不建议假设本机能同时跑多个长上下文视觉 agent 或持续承担高质量整页生图。应先测实际峰值显存/内存及单页历时，再决定模型和队列。

## 实施优先级与验收

| 优先级 | 改动 | 预期减少 | 验收依据 |
|---|---|---|---|
| P0 | 将调度、续约、下载/提交/缓存恢复交给代码；标准化独立任务文件与短回执 | agent 调用次数、重复领取/重做和上下文协调 | 失效 token 不提交、工具成功后不重跑、自动续约、真实产物恢复 |
| P0 | 证据包去重与按章节处理；补 key_points 审查覆盖合同 | 重复输入、漏审与合同误解 | 全237页覆盖不变、引用/限定上下文保留、审查必须逐条完成 |
| P1 | 本地 OCR/版面候选及 CLAIMS、FACTS 草稿 | 云端全文转录与候选选择 | 用已独立复读的页做盲测，数字/单位/符号/格位误差逐项报告 |
| P2 | 本地 SUMMARY/DECK 草稿，独立审核继续保留 | 首稿云端阅读和页面组织调用 | 对照当前修订前后错误：且/或、区间、最长时间、作用人群、关联/因果等 |
| P3 | 本地正式语义复核及视觉布局自动匹配的资格实验 | 复核与布局调用 | 非自身输出评测；逐项支持判断及错误分流，质量未过关时拒绝路由 |
| 后续实验 | 本地去字/描摹/生图 | 部分图像工具调用 | 同一设计/锁定内容下评视觉和编辑性；需要与当前工具回执/路由单独兼容设计 |

费用核算要分开：代码执行时间、本地 GPU 时间、云端输入/输出或工具调用量、修订与重试、人工作业。模型改为本地后仍消耗推理算力，SaaS 部署需要计入 GPU 购置/租赁、容量、维护和闲置；这不能用「零 token 账单」代替总成本。

本次没有各阶段实际云端 token、供应商费用或本地推理基准，因此不报告节省百分比或每套课件的新价格。首阶段可先实测同一批长文本、密集表格和流程页，量化输入字节/实际token、峰值资源、耗时、失败率及修订次数，再决定主线路由。

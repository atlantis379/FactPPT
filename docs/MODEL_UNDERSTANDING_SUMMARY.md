# 模型理解原文并同步建立证据索引

需求确认：2026-10-14。适用于FactDeck主线新的SUMMARY任务。

## 用户目标

模型阅读完整文章、章节和段落，先形成作者主旨、组织依据、结论及关系的理解结果，再形成忠实总结。同时建立可追溯的证据、数据、条件、限制和风险索引。代码负责文件提取、引用定位、去重和确定性校验。准确理解是本阶段目标，不以压缩率、字数或要点数量评价成功；受众用于解释术语与背景，不能成为删去关键条件的理由。PPT页数、密度和展示取舍留到DECK。

当前242条内容包含引用拆分和重组产物，不能因逐字匹配通过就视为242个经过教学价值判断的重点。验证副本使用过的“每两条论断一组”脚本仅为历史实验，不再作为新任务的总结方法。

## 算法整改范围

1. SUMMARY任务向模型提供原始页/单元的完整上下文和论断索引；先理解后选择，不按引用条数、字数或固定要点数量决定重点。表格、图示等必须使用已有真实视觉读取证据。
2. 模型同时输出自然语言总结、重点选择理由、上下文与必要限定、关系依据、逐字证据索引，以及各来源页纳入/参考/待定的理由。
3. 总结允许来源支持的归纳；逐字证据单独存储。资料原话、模型归纳及待裁定内容保持明确的来源属性。
4. 程序检查索引覆盖、引用位置、数值/单位/比较符号是否在引文中、索引版本和依赖；程序不评价教学价值，也不把按块复制视作语义理解的证据。
5. 独立总结审核同时收到总结、选择理由和证据索引。原有独立身份、逐条判定、问题台账及人工内容确认继续有效。
6. 事实库候选在SUMMARY验收时由已核验索引生成并存档。FACTS任务复用候选，补充细粒度切分、实体/属性与冲突信息；不再要求为既有要点全量重新理解原文。
7. 采用新的版本标记绑定任务合同。历史总结与已经领取的旧合同保持兼容，不追认它们满足新算法。

## 验证标准

- 新SUMMARY合同须明确要求模型理解上下文、选择理由、必要限制和同步证据索引。
- 每个要点均有选择理由与main证据；证据逐字存在于原始单元。
- 每个来源页有明确处置理由，参考页与待定页仍有索引。
- 数据条目引用同一已核验引文；不由正则表达式推断统计含义或生成医学关系。
- 限制从参考页跨入教学内容时显式标待定，保留人工裁定，不能靠索引绕过已确认结构。
- 修改总结会使相应索引候选版本失效；后续事实库不能接受旧版本候选。
- 新旧合同兼容、人工关口和现有原生PPT主线测试通过。

## 本次变更界限

当前18项待确认问题保留。此次为算法与开发流程整改，不自动重写现网总结、记录内容确认或生成PPT。模型能力改善需要同一章节的独立实测，合同和代码测试不能替代该实测结论。

### 先理解、再总结（2026-10-14第二次整改）

`source_understanding.v1`覆盖所有有要点的章节：

- `author_message`：作者在讲什么，核心问题和结论。
- `organization`：作者为何这样组织；区分`SOURCE_SUPPORTED`和`ANALYST_ORGANIZATION`。无法从原文证明作者意图时，明确为模型组织建议，不能伪造作者动机。
- `conclusions`：结论、`conditions_and_limits`、总结`point_ids`及`evidence_refs`。先形成结论，再写对应总结；最终结果用绑定编号追溯。无条件或限制时也明确说明，不猜测。
- `relations`：前提、因果、相关、比较、并列、时序、例外、支持，使用结论编号作为端点。来源支持的关系必须绑定证据；模型组织建议不得充当医学关系。
- `relation_assessment`：说明关系判断和未成立的关系；没有关系时可以是空列表，不强制画箭头或编造连接。

证据引用格式为`point_id/evidence_id`，复用现有逐字索引。代码核验章节/要点覆盖、结论端点、证据存在及归属、来源属性；不能证明作者主旨与关系在语义上正确，也不能单靠JSON字段证明模型实际思考顺序。独立审核必须针对原文核对这些内容。

关键阈值、必要条件、否定、例外、阴性分支必须在point正文明确表达，图引用或索引存在不能替代总结表达；point不能仅是主题目录，context用于补背景，不承担被正文省略的核心规则。总结阶段没有长度/数量上限，不要求与已选PPT页数相称。已批准结构的来源分配仍保留。

索引`points`逐一记录`point_id`、`selection_reason`、`context`、`evidence`、可选`data_items`和`figure_ids`。证据含`id/unit_id/quote/role/usage`；程序记录原始单元位置`start/end/source_quote/page_id`及转录待确认标记。data_items记录`evidence_id/meaning/value/operator/unit/context_quote`，语义由模型判断，字段逐字存在性由程序核验。

已有论断片段优先用`claim_id/span_index`引用，由代码解析引文和位置，不要求模型重复输出整段原文。需要细分或补缺时才提供`unit_id/quote`。这同时降低输出量，并避免抄写数字时引入错误。

`page_decisions`覆盖每个来源页，记录`TEACHING/CONTEXT/REFERENCE/PENDING`、理由和要点对应关系。参考/跨章节限制只能标PENDING，并用`pending_issue_index`绑定实际未决事项，不能靠索引绕开来源分配。

SUMMARY验收同时保存版本绑定的`summary_fact_candidates`快照；FACTS合同按总结校验值读取此候选及绑定，版本变化即不复用。SUMMARY_REVIEW收到同步索引，先独立判断原文支持，再核查选择理由和遗漏。人工确认及正式事实库关口继续由现有代码执行。

`tools/prepare_fact_candidates.py`对于新算法只复用模型索引，不再自行按论断分组；历史总结保留逐字候选准备兼容入口，该入口不代表完成模型理解。

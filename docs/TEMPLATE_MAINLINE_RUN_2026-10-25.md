# 模板库主线：接入与全流程测试记录（2026-10-25）

## 一、做了什么（优先级 ②：`/api/deck` 默认走模板库）

- 新路线 `generation_route: "TEMPLATE_LIB"`，**新项目默认**（`app/deckflow.py` `TEMPLATE_ROUTE`）。已有项目保持原路线：
  `A_NATIVE_VECTOR` 只供已有项目，`CODE_NATIVE` 保持不变。
- DECK brief（模板路线）：给出 `template_library`，列出每个版式的槽位（紧凑写法 `*≤16` / `name[≤4]`）、关系和降级目标。
  模板规则放在最前；旧版式的构图规则（composed / flow / chart / emph 等）不再下发。结果示例全部写成模板页。
- 提交 DECK 时：模板路线要求每页都是 `layout: "template"`，封面和章节页用 `template.kind` 标为 cover / section。
  `deck.check` 不允许模板页和旧版式页混排，每份 deck 只对应一个渲染器。
- RENDER：模板 deck 改走 `factdeck/template_lib/render_deck.py`，输出约定与 `factdeck.render` 相同
  （deck.pptx/pdf/html、slideNN.png、render_report.json），因此页面审核、视觉评审和交付流程都不用改。另外输出
  `template/trace.md` / `trace.json`，PPTX 备注里加【讲稿】和【溯源】。
- 硬错误：页面未渲染、测量发现溢出或截断、事实没有完整出现在对应页的 PPTX 里、PPTX 中出现图片或嵌入 SVG。
- 在模板路线上调用 `generate`（`POST /generation`）就是代码渲染，不再排视觉任务。界面文案按项目路线显示，
  并提供 trace.md 下载。
- 交付：trace.md / trace.json 纳入渲染记录的哈希清单，打进交付包；文件被改动时拒绝交付。
- 语义审查（RELATIONS）：模板页的"版式结构"检查项里给出选版式器决定的版式、是否图表和理由。

## 二、全流程测试

`tests/test_template_mainline.py`（4 项，全部通过）：

- 从读源、总结、内容确认、事实库、DECK（9 个模板页）、两张语义审查清单、冲突处理、第二次转录、渲染，
  到前 5 页审核、风格确认、其余页审核，最后交付。交付包里有 trace.md，篡改 trace 后交付会被拒。
- 模板路线拒绝旧版式页。DECK brief 只下发模板内容。
- 通过 HTTP 接口走 `POST /generation` → 渲染，`GET …/render/final/trace.md` 能拿到报告，health 报告默认路线。
- 两项研究人群不同、原文写明"不能直接比较"的那一页用对照页，不画柱图（断言检查了这一点）。

结果（9 页）：0 硬错误；33 处事实全部在 PPTX 中逐字找到；0 张图片、0 个嵌入 SVG；模板渲染总耗时约 2.1 s
（其中 measure 约 1.9 s）；模型 token 为 0（渲染不调用模型）。

**PowerPoint 核对**：本机装有 Office 365，渲染时自动用 PowerPoint（COM）导出每页，与浏览器渲染比对。9 页的像素均差
都在 0.006–0.016 之间，阈值是 0.06。截图由我逐页看过：文字、表格、形状、连接线都是原生对象，没有走样。
没有 PowerPoint 时退回 LibreOffice，也没有 LibreOffice 时在报告中说明未核对。WPS 尚未核对。

## 三、发现的问题、判断与处理

| # | 问题 | 判断 | 处理 |
|---|---|---|---|
| 1 | 本机没有 Playwright Chromium，所有浏览器测试都在静默跳过（含 `test_template_native`） | 环境问题，导致此前的"通过"不可靠 | 已安装；全量失败数从 62 降到 22（剩下的均为缺少的旧夹具或资产文件） |
| 2 | Windows 下渲染目录路径超过 260 字符时，Chromium 打不开 `file://` 页面，渲染失败 | 真实缺陷（项目编号 + 渲染编号 + 嵌套目录很容易超长） | 页面 HTML 不依赖外部文件，改用 `set_content` 加载，与路径长度无关 |
| 3 | 章节页的大号序号显示为"0"（执行端写了"一"） | 序号属于版面元素，不应由执行端写 | `number` 改由代码写入（按章节顺序 1、2、…），填充中写了会被拒 |
| 4 | 只有 1 条要点的卡片页，一个深色大块占满整页 | 内容形状不适合这个版式 | 提交时给出提示：并入相邻页，或拆成 2–4 条 |
| 5 | 内容少时，卡片和对照栏拉满到底部，显得空 | 模板视觉问题。试过"卡片高度随内容"，在 COPD 样例的满页内容上反而更差（中间空出一块） | **已撤回改动**，留作模板迭代项，等医生反馈后统一调整，不在全流程测试里改已调过的模板 |
| 6 | 测试把 job 统计写进真实的 `data/job_stats.sqlite`，会污染耗时和 token 基线 | 真实缺陷 | 新增 `tests/conftest.py`，测试统一写临时库；删除了本次产生的 7 条测试记录（均为临时目录） |
| 7 | 交付包里没有溯源报告；trace 文件没做哈希校验 | 不符合产品承诺"附溯源报告" | trace.md / trace.json 纳入哈希清单并打包，被改动时拒绝交付 |
| 8 | 语义审查员看不到模板页最终画成什么版式 | 审查员无法判断画法是否暗示了原文没有的比较 | 关系检查项里给出决定的版式、是否图表和理由 |
| 9 | 模板路线的 DECK brief 比旧路线大 14%（45.1k 对 39.7k 字符） | 对 token 成本不利 | 槽位改成紧凑写法，现在 36.4k，比旧路线少 8% |
| 10 | `test_default_route_and_original_gates` 断言默认路线是 A | 测试固定的是已作废的决定 | 按新决定改为 TEMPLATE_LIB，并保留"可显式选 A"的断言 |
| 11 | 测试 deck 里相邻两页版式相同、图表页占比为 0 | 由内容决定（没有可画成图的数据），选版式器正确降级 | 渲染报告给出提示，不算错误 |

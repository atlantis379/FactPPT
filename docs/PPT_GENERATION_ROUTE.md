# PPT 生成方案：A 原生矢量路线

## 已确认的方向（2026-10-01）

用户决定：“那现在的PPT生成方案就固定为 A，生成图然后进行矢量化，文字填充”。

项目后续 PPT 视觉制作采用 **A 原生矢量版**：

**锁定内容和共同设计说明 → 生成带文字完整设计稿 → 去字 → 图形矢量化 → 转成 PPT 原生形状 → 填入原生文字、表格、数据与连接线 → PowerPoint 渲染核对。**

用户对可编辑性的要求：“所有图形都变成原生矢量，可改轮廓和颜色；允许部分纹理细节损失”。完整生图稿确定构图与视觉语言；最终文字和关系来自经过核对的内容。B 的纯代码视觉重绘保留为实验对照。此前 A 保留整张位图背景的版本是历史中间成果，最终采用上述原生矢量版。

本决定取代此前“主线不生成插画／只以纯代码决定视觉”的方向限制。事实库、来源追溯、独立语义审查和人工确认要求继续适用。决定的结构化记录见 [decisions/ppt_generation_route_a.json](decisions/ppt_generation_route_a.json)。

## 每页的制作约定

1. **锁定内容。** 保存每页事实引用、逐字显示文本、数字、单位、比较符号、限定条件、来源备注和待确认标记。写明第一眼焦点、阅读顺序、文字区、容量与组件关系。
2. **完整设计稿。** 让模型生成带文字的完整页面，建立同一套配色、字体气质、图形与装饰。保存实际图片、完整提示词、参考图、工具回执、耗时和文件校验值。生图中的文字、箭头和数据不能作为新的事实依据。
3. **去字与分离。** 去除设计图中的文字、数字、表格文本及会被原生关系图替换的错误连接。检查残字；生图稿中错误的医学关系要移除后按锁定输入重建。
4. **矢量化图形。** 保存实际 SVG，转换为 PPT 原生自由曲线、线条和填色，按肺部、图标、波纹、容器等可操作组件归组。SVG 作为转换输入，不能以 SVG 图片或整页位图代替原生路径。
5. **填入原生内容。** 文字使用原生文本框；表格逐格构建；数字、单位、限定条件与来源逐项填回；条形与流程连接线按来源支持的数值和关系由代码构建。保留全部锁定内容，密度过高时重新编排或拆页。
6. **配色与画面调整。** 直接调整原生对象的颜色和轮廓；保留组件分组，记录纹理、渐变及局部轮廓损失。改变配色不必重复生图或矢量化。
7. **实际交付检查。** 回读全部事实、表格单元格与来源备注，检查残字、溢出、遮挡和连接方向。用安装的 PowerPoint 渲染实际 PPTX，逐页看图并抽样验证组移动、路径改色和顶点修改，输出 PPTX、PDF 和逐页 PNG。

生成的视觉元素不得增添未经来源支持的药物、机制、数值或医学关系。原件证据图片继续遵守 [FIGURE_REFERENCE.md](FIGURE_REFERENCE.md)，生成图不替代来源证据。

## 主线自动编排（2026-10-01）

**A 已接入 FactDeck `/api/deck` 主线，新项目默认路线为 `A_NATIVE_VECTOR`。** 执行端采用用户选定的 Codex＋Adobe；应用自动排队、验收、存档和串联任务，不在服务器中模拟工具调用。工作台“渲染与审核”中的“开始／续跑生成”启动同一入口。

### 每页任务链

| 任务 | 执行端交回 | 下一步 |
|---|---|---|
| `VISUAL_DESIGN` | 原生 ImageGen 实际 PNG、完整提示词、参考资产校验值、真实调用回执与检查记录 | 自动排版面拆解；首张设计稿成为其余页的视觉参考 |
| `VISUAL_LAYOUT` | 查看实际设计稿后，提交全部锁定对象的坐标、字号、颜色和组件区域 | 程序拒绝替换文字、遗漏对象、越界和数据图形比例变化；自动排去字 |
| `VISUAL_CLEAN` | 实际去字 PNG、编辑调用回执；确认已查看输出、无残字并移除待重建的语义图形 | 自动排 Adobe 矢量化 |
| `VISUAL_VECTOR` | Adobe 实际 SVG、调用回执 | 检查纯矢量输入；全部页面完成后，程序自动导出 |

准备阶段用已有代码引擎生成内容锁：文字、每个表格单元格、原件图、来源备注和已支持的连接关系。执行端可调整版面，不能提交替换文字。原生箭头保留原端点对象与方向；数据图形的几何锁定。首张设计稿修订会让整套设计重新生成，其余页面可单独从指定步骤重做。

程序将 SVG 转成可改轮廓及颜色的 PPT 自由曲线并按组件区域分组，填回原生内容，回读核对，检查浏览器溢出及重叠，再用 Windows 上已安装的 Microsoft PowerPoint 输出 PDF、逐页 PNG 并测试组件移动、改色和顶点编辑。生成图形不能以 PNG 或 SVG 图片导出。经许可的原件证据图和客户品牌标志保留实际文件；它们不属于生成图形。

版面拆解支持文本框字体、字重、行距及逐段字号、颜色；逐段样式须完整覆盖锁定段落，不接受替换文字。浏览器预览与原生PPT使用同一字体名；执行端应选用本机已安装的字体，并在实际PowerPoint画面中核对。未提交这些可选属性时沿用原行为。

原生表格也支持字体、字号、行距及完整列宽/行高列表；列表须与锁定行列数量、外框尺寸一致，文字与单元格不可替换。浏览器测量单元格的真实字体基线，并阻断表格自动扩高、行扩高以及表格与文字遮挡。

填回原生文字时，浏览器逐字测量紧凑粗体标题：仅在原字号20–40px、两行且末行只有一个字符、首行至少10字符时，先在无碰撞的同一图形容器内尝试扩宽最多16px，再按不超过11.5%、不低于19.5px微调字号；实际测量能成为一行才采用。原文与文本框位置不变，具体变化写入最终模型和逐页渲染报告。不能用这个规则压缩长正文或隐藏内容。

A导出保留锁定文本框宽度，不再使用旧导出器对所有文本框统一加宽3%的行为；旧代码路线沿用原默认。表格边线按DrawingML规定放在填充节点之前，避免PowerPoint忽略浅色边线而显示默认黑色网格。Office另外检查实际字形边界。若字体度量造成多换一行，仅在不越界、不碰相邻文字或表格、且不越出图形容器时，按实际测量增加1–16px宽度，直到Office实际高度和宽度均通过；保存调整后的原生PPT，并重新检查浏览器。调整逐项存档，原文、字号和位置不变。不换行文字或独立数字在空白中不超过16px的字形横向外沿差异单独记录；其余实际溢出阻断。

原生导出器版本独立进入渲染校验值。版本更新后使用原 `generate` 入口重新编译已有完整素材，不增加模型任务或工具调用；仍保留来源完整性、事实与人工确认检查。

去字合同按锁定模型是否存在原生表格生成：表格页面要求删除整块表格并补齐纸色，交由原生表格填回；无表格页面明确保留卡片外框、底色、标题色带、图标轮廓与装饰短线，避免把卡片误当空表格删除。失败输出仍须实际查看、记录并从相应步骤修订。

任务和代码导出状态存于原有 SQLite 工作流。内容版本、输入资产或版面变化会使任务及页面审核失效；重复启动复用当前资产。执行端租约15分钟、最多3次尝试，失败后可“续跑”；耗时导出在事务外执行，用持久租约防止重复发布。服务启动及运行时恢复待执行的代码导出，进程中断的运行任务需等待租约过期（最长1小时）回收。导出错误保留具体原因，修订对应页面或修复环境后续跑。

调用量、执行端任务尝试及重试、已提交工具耗时、资产字节数、准备与渲染耗时、PPT/PDF文件大小和矢量差异均存档。未提交的外部调用无法计数；没有真实费用数据时不估算费用。回执属于执行端提供的记录，不是厂商签名的计费凭证。交付包包含设计稿、去字稿、SVG、回执和布局记录。

中断后恢复的真实输出若缺失返回耗时，回执使用 `elapsed_seconds:null`、`timing_status:UNKNOWN_AFTER_INTERRUPTION` 和具体说明；该调用仍须有真实输出、调用标识、完整提示词与资产校验值，并实际查看。缺失耗时单列计数，不填零值。并发调用的墙钟耗时含队列等待，汇总不能当作整套实际历时。

调用量同时计入页面修订前存档的真实回执，按工具和调用标识去重。原生导出按真实浏览器字体度量补足最多16像素的文本框高度，仅在不越界、不与相邻文字重叠且无横向溢出时调整；字号、位置和文字保持原样。调整写入渲染报告和最终 `native_model.json`。更大溢出、表格溢出和重叠继续阻断导出。

页面角色（2026-10-13）：版式为 cover / divider / closing 的页面是封面类，可用版画式插画作整页背景，并以首张设计稿为风格参考；其余正文页的主体须是解释本页信息形状（分类、对照、条件、范围）的说明图，不沿用封面风景底图，装饰只限角落少量叶片。项目绑定已确认视觉标准时，正文页的参考图为该标准正文样页的实际无字清图（按标准中记录的校验值核对，经 `/visual-standard/{name}` 提供）。此前所有页面都以封面设计稿为参考，导致正文页统一成“风景底图＋图标＋文字”，偏离了标准中“图形必须解释本页原文”的要求。

正文页插图通用标准（`config/visual_grammar.json`，visual-grammar.5，与主题无关）：插图把原文陈述的关系画出来。规划单位是“原文陈述的一个关系＋它的各项”（类别、条件或任一/全部、先后、分支、条件→做法、因果、变化、对照、对应、适用范围、包含、阈值、比例、时间框架、目的→手段，或单一事物）。方案逐单元写明原文片段、关系类型与原文关系词句、各项（逐字片段），以及封闭的作图清单：每个对象要么就是某一项原文点名的事物，要么属于允许派生（通用示意符号、变化前基线、状态载体、虚线表达“可能/将来”、无字占位），并绑定到它表达的那一项；清单外不画。程序按语言连接词为每段给出候选关系（只作提议）；焦点段落必须配图，含候选关系的段落须配图或以规定原因略去。`design-prompt` 先检查方案再生成提示词，生图提示词只含作图清单。生图后由不同于设计与去字作者的执行端对去字图独立盲读（`VISUAL_BLIND_READ`，只看去字图和本页原文，不看方案），列出图中对象及其对应原文、读出的关系；程序与方案比对，出现对应不到原文的对象、读不出的关系或认不出的项即为 FAIL，整套导出需全部 PASS。表格、原件图、数据图和目录页不另画插图。规则问题按关系类型调整，不逐页改提示词。

2026-10-13 起推荐用 `submit`（程序按合同生成回执）和 `layout --inspected [--patch]`（默认版面＝内容锁几何）代替手写回执与版面文件；两者都可加 `--next-out` 直接续领同页下一步。版面提交时即做与导出相同的溢出/重叠预检；矢量提交后自动生成单页 PowerPoint 预览及对比度、遮挡信号。批次窗口、双执行端分工和计时工具见 [PARALLEL_WORKER_PLAN.md](PARALLEL_WORKER_PLAN.md) 的“吞吐改进”一节。

多执行端按页领取时使用 `claim --binding PAGE_ID`，各端独立任务文件和worker身份；提交可加 `--compact` 减少完整状态传输。`tools/visual_worker_runtime.py` 提供独立续约与工具并发锁，当前限额ImageGen 1、Adobe 2、浏览器1；本次由协调agent分配页面，最终Office检查及人工门槛保留。具体用法及实现边界见 [PARALLEL_WORKER_PLAN.md](PARALLEL_WORKER_PLAN.md)。

HTTP 接口：`POST/GET /workflows/{id}/generation`、`POST /generation/revise`、`POST /tasks/{task}/asset` 和按页访问的生成资产。均位于 `/api/deck`；JSON任务沿用原领取、完成、失败和续约接口。`render?draft=true` 用原代码引擎检查内容；旧项目未选择 A 的历史渲染保持兼容，在工作台启动生成即切换 A。`/api/fact` 与原语义接口继续保留。

`{"kind":"PREFIX","page_count":15,"total_pages":50,"base_page_ids":[…整套编号…]}`。
本次范围之外的页面必须与原规格一致。事实核对、语义复核和人工确认继续约束范围内每页。
原批准的核心句和完整关系保留为语境，不将关系截短后当成新关系。

```powershell
python tools/codex_worker.py generate FLOW_ID --first-pages 15
```

SVG当前支持路径、分组、仿射变换、纯色和线性渐变；近白纸张颗粒省略、颜色按4级量化、渐变用平均色近似，均报告差异。图片嵌入、文字节点、脚本、外部引用、遮罩、滤镜、裁剪与未支持样式会拒绝，不能回退成图片。复杂纹理与相交图形的组件归属仍可能需要修订；自动检查不能判定审美或识别所有描摹残字，最终逐页审核继续承担这些检查。

自动编排已接入；真实工具调用仍需在线的 Codex＋Adobe 执行端，尚未提供服务器独立调用厂商 API 的无人值守能力。50页批量耗时、失败率与真实费用仍待实测。后续优化在主线的任务合同、组件拆解和原生导出层进行，不再以实验 B 的简化重绘作为默认输出。

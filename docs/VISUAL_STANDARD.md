# FactDeck 视觉标准：A 原生矢量路线

## 当前生成方向与视觉起点（2026-10-01）

用户已固定采用 **A：生成完整设计稿 → 去字 → 图形矢量化 → 原生文字、表格和连接线填充**。
完整流程、内容边界和接入状态见 [PPT_GENERATION_ROUTE.md](PPT_GENERATION_ROUTE.md)。
当前视觉参考为 `output/visual_ab_test/A_vector_muted/deck.pptx` 的六页低饱和样本。

标题重点及关键数字用墨蓝 `#355E78`，表头用蓝灰 `#3E6278`，正文炭黑 `#151B24`，背景米白 `#F6F4EF`。
插画按原明暗映射为灰蓝，波纹进一步降低对比。标题、数字和背景不同时使用大面积高饱和亮蓝。
图形全部转为原生路径，保留组件分组、填色和轮廓编辑，允许部分纹理细节损失。
配色样本是当前默认起点，路线确认不等同于正式风格或逐页审核通过。
应用已将此路线设为主线默认，工作台生成入口自动串联 Codex＋Adobe 任务和原生导出。原生结果须经PowerPoint实际渲染和逐页审核；自动检查不能替代审美判断。

以下 `factdeck_demo`、代码模板及其深蓝/青绿、仅贴边装饰等规则是旧渲染器的兼容参考。
A 路线的视觉选择以当前设计说明和本节配色为准；事实完整性、并列同等处理、限定条件、可读性、
来源追溯和实际 PPT 检查继续适用。旧模板具体字号和装饰限制不强制覆盖 A 的生图构图。

## 已有代码渲染器的兼容标准

基准：`output/factdeck_demo`。字体：微软雅黑（常规、粗体两种字重）。
本标准落在三处：

1. **设计令牌**：`factdeck/templates/deck.html.j2` 的 `:root`，模板只能引用令牌；
2. **自动检查**：渲染报告中每页的 `design` 指标；
3. **页面审查评分表**：见本文末尾。

## 原生 PPT 基线样本

固定参考文件：`output/factdeck_demo/deck.pptx`（SHA-256：`551F03F42625ED0610DE158B2F2F83ACB39F110C0A60144510123277055F0E3F`）。它是 16:9、6 页的**视觉和可编辑性样本**，不是医学内容、跨研究比较或客户确认状态的正确性样本。样本包含 85 个文字框、50 个原生形状、18 条连线、2 张原生表格和 1 张图片；仅封面使用图片，内容页由原生对象构成。

| 样本页 | 可复用的视觉做法 | 检查同类页面时看什么 |
|---|---|---|
| 1 封面 | 深色底、标题主导、配图退居一侧 | 标题一眼可读；配图不承载未经核对的正文 |
| 2、6 表格 | 深色表头、浅色交替行、来源与备注分层 | 单元格可读；长段落先拆分信息再入表 |
| 3 指标卡片 | 等宽卡片、大数值、短标签 | 每卡一个重点，数值与限定条件同屏可见 |
| 4 流程 | 节点、箭头和旁注各有层次 | 路径能顺序读出，箭头文字不拥挤 |
| 5 对照 | 双栏等权、关键数值突出、底部限制说明 | 对照关系有事实支持，限制不会被视觉弱化 |

验收以渲染后的每页画面和 PPTX 可编辑对象为准：自动报告通过只是基础门槛，还需按文末评分表逐页目视审查。六页样本只定义表现方式，不要求整套演示复制这些页的具体内容或布局比例。不同客户模板须保留其授权和主题，以这些信息层级、密度与可读性标准作对照。

当前渲染报告已有事实回读、溢出、越界、重叠和层级检查，并逐页输出 `occupancy`（主体向下用到版心的比例）和 `hole`（最大空白区占版心的比例）；`min_font`、`contrast` 等尚未实现，不能记作已自动验收。

## 一页一个设计方案：规则与提示

每页按自己的内容构图，不让所有页面服从同一种版式。为此把要求分成三类：

| 类别 | 内容 | 处理 |
|---|---|---|
| **规则**（硬错误，每页都适用） | 事实逐字；节选不得删去否定、限定词；删去“中国：”这类范围标签时本页须另有事实写明它（整组只写一次）；并列的各项（同一 `peer` 键）同等处理；条形长度与数值成比例；箭头须有原件箭头或被依次拆开的同一句原文支持；字号层级、溢出、越界、重叠；PPTX 回读 | 不满足即不能渲染或通过审核 |
| **语义审查项**（逐页列出） | 引文中的强调（`emph`）、删去了文字的节选、把一句原文拆成先后环节 | 交语义审查逐条确认 |
| **提示**（逐页给出位置） | 留白（主体用不到版心的 60%，或最大空白区超过版心的 20%）、同一文字在本页重复 | 按这一页的内容去改，或在 `design.exceptions` 中写明理由（如“时间轴左段的空白是真实的年代间隔”）；写明理由的提示不再作为警告 |

规则来自意义和可读性，任何页面错了都是错的；构图、第一眼看什么、如何用留白由每页自己决定。

**设计说明（`design`）**：每个内容页先写这一页的方案——`first` 第一眼看到什么，`then` 随后读什么，`reference` 供查阅什么，`strong` 唯一的强元素及为何用这种形状，`exceptions` 对提示的说明。逐页审核时说明与画面、提示并排显示。

**逐页构图（`composed`）**：固定版式是起点；内容需要时，页面用 `composed` 在版心上放置文字、面、线、标记、条形和箭头（全部可导出为原生 PPT 对象），见 `factdeck/compose.py`。

**重点不靠把并列项之一涂深**：两份指南、两条通路、几种药物是并列关系，须同等处理；重点用位置（靶点挂在所属通路下）、关系和局部标记表达。只有包含关系的最内层、流程的终点这类本身就是核心的元素，才用唯一的深色。

## 渲染方式与构图方案

**现有“浏览器排版 → 原生 PPT”实现**：浏览器量出文字框与形状，再重建为原生对象并回读事实。A 路线继续复用文字测量与原生导出，增加完整生图参考、去字和实际图形矢量化；最终交付使用原生路径，不以整页生成图替代可编辑页面。

**导出的 PPTX 结构**：页面标题放在真正的标题占位符中（大纲视图、导航和读屏软件能识别）；主题写入配色与字体（微软雅黑），页面上与主题色相同的颜色写成主题引用，客户在“设计 → 变体 → 颜色”中换色即可整套换色；构图方案中的一个单元（一条通路、一行、一栏来源、一组条形）导出为 PowerPoint 组合，移动时整体移动。已安装 LibreOffice 时，渲染报告还会把 PPTX 的画面与浏览器画面逐页比对（未安装时注明“未比对”）。

**构图方案（recipes）**：逐页构图时优先写 `recipe` + `slots`，由程序按内容长度放置，不必写坐标（`factdeck/recipes.py`）。渲染时先量出每个文字块在浏览器中的实际高度，再按实际尺寸重新放置一次。

| 方案 | 适用的内容形状 | 参考页（试点） |
|---|---|---|
| `clause_rows` | 2–3 份来源逐条对照（指南定义、研究终点） | 国内外指南对重度哮喘的定义 |
| `nested_sets` | 包含关系 A ⊃ B ⊃ C，圆内只放名称与数值，旁列定义 | 未控制、难治性与重度哮喘的关系 |
| `step_rail` | 自上而下的步骤 + 证据栏（数值、原件条形、研究说明） | 诊断前的系统评估 |
| `value_bars` | 一个关键数值 + 一至三组条形，只涂深被主张的一组 | 疾病负担 |
| `lanes` | 并列的过程/通路，附属信息挂在所属的一道下 | 2 型与非 2 型炎症及靶点 |
| `date_axis` | 多个对象的多种日期，同一时间轴，图例只写一次 | 已上市生物制剂一览 |
| `entity_rows` | 每个对象一行、属性分列，一格可多条 | 适用人群与其他适应症 |

没有合适方案时仍可直接写 `blocks`。

## 版面指标与评审

渲染报告逐页给出以下指标，超出阈值时作为**提示**（页面可修改，或在 `design.exceptions` 中写明理由）：

| 指标 | 含义 | 提示阈值（按试点页校准） |
|---|---|---|
| `occupancy` / `hole` | 主体向下用到的比例 / 最大空白区占比 | < 60% / > 20% |
| `balance` | 墨迹重心与版心中心的距离（1 为居中） | < 0.75（试点页 0.83–0.91） |
| `alignment` | 与其他文字块共用左对齐线的比例 | < 0.6（试点页 0.71–1.0） |
| `type_sizes` | 正文字号种类（14–23 px；注释、标签和数据大字不计） | > 3 |
| `strong_areas` | 深色区块数（条形是数据标记，不计） | > 1 |
| `regularity` | 同一栏内上下间距的一致程度 | 仅报告，不提示 |

构图方案连续用于 3 页以上也会提示（同类内容可说明理由）。

**版面评审（VISUAL_CRITIQUE）**：正式渲染后，由页面作者之外的执行端逐页看图，对照设计说明和评分表逐项给出 PASS / REVISE，并写出具体修改意见；意见进入下一轮页面编写的任务说明（至多两轮）。评审只是建议，不记录逐页审核，页面仍由人审核通过。

## 五条原则

1. **一页一个焦点。** 每页只有一个最强元素，其余都退后。最强元素是以下之一：深色结论条、主数字块、流程图核心节点、表格表头。
2. **克制用色。**
   - 主色（深蓝）用于结构：标题、表头、核心节点、结论条；
   - 强调色（青绿）只标数据和标记：大号数值、卡片顶边、圆点、箭头标签；
   - 其余用中性色。
   - 面积大致为：白 ≥ 70%，中性浅色约 20%，彩色 ≤ 10%。
3. **固定的字号阶梯。** 层次来自字号与颜色的对比。微软雅黑只有两种字重，不用加粗之外的手段制造层次。
4. **留白是版面的一部分。** 内容少时保留留白，不放大文字，也不凑内容。内容多时拆页，不压小字号。
5. **一致比新奇重要。** 同一种信息始终用同一种版式、放在同一位置。内容页的装饰只有贴边色条；不加图标、渐变、阴影。封面和章节页的配图除外。

## 可量化的规则

| 维度 | 规则 | 令牌 / 检查 |
|---|---|---|
| 字号阶梯 | 标题 34，导语 17，正文 16–17，标签 13–15，数据大字 44–48，主数字 80；最小 12 | `--fs-*`；`min_font` 低于 12 为**硬错误** |
| 层级 | 较长的正文字号不大于标题 | `hierarchy` 为**硬错误**（已有） |
| 间距 | 8 的倍数：8 / 16 / 24 / 32 / 48；页边 64 | `--sp-*` |
| 圆角与描边 | 容器 10，大容器 12，胶囊为高度的一半；描边 1px，强调顶边 4–5px | `--r-*`、`--bw-*` |
| 表面层级 | 白底细边为内容区，浅色为说明区，深色为唯一强调区 | `dark_blocks` > 1 提示（不计表头） |
| 用色 | 强调色只标数据与标记 | `accent_blocks` > 6 提示 |
| 密度 | 主体向下用到版心的 60% 以上，最大空白区不超过版心的 20%（提示，可在设计说明中说明理由）；正文字数 ≤ 220；为放下内容收紧到 0.85 以下即提示拆页 | `occupancy`、`hole`（已实施）、`body_chars`、`density` |
| 字号种类 | 主体区最多 3 种字号（数据大字除外） | `font_sizes` > 3 提示 |
| 对齐 | 块的左边缘落在 12 栏网格上（容差 2px） | `off_grid` 提示 |
| 数字排版 | 等宽数字；大号数值中的单位与比较符号缩小一级、颜色变浅，文字本身不变 | 模板自动处理 |
| 对比度 | 文字与背景对比度 ≥ 4.5，大字（≥ 24px）≥ 3 | `contrast` 为**硬错误** |
| 节奏 | 连续 4 页只用列表、陈述或表格时提示；纯文字页 ≤ 30% | 页面规格检查（已有） |

硬错误只有三项：最小字号、对比度、层级。它们关乎能不能看清。其余都是提示，写入渲染报告，供编写和审查参考。

## 内容选择（写给页面编写者）

- 先确定每页的焦点，再决定版式：一个关键数值用主数字页，几个并列指标用卡片，流程或路径用流程图，逐项对照用表格。
- 内容很少时（例如只有几个短标签）选择更有分量的版式，比如卡片或主数字页，不要让大片空白压住少量文字。
- 单页正文不超过约 220 字，列表不超过 6 条；超过就拆页。

## 页面审查评分表

逐页判断“通过 / 需改”，任一项需改，页面就退回修改。

| 项目 | 通过的标准 |
|---|---|
| 焦点 | 一眼能看出这页的主角；没有两个元素争抢注意力 |
| 用色 | 彩色只出现在数据和标记上；深色区块不多于一个 |
| 字号层级 | 标题、导语、正文、数据四级清楚；没有比标题还大的正文 |
| 留白与密度 | 留白服务于内容：没有无意义的大片空白（见提示及其说明），也不拥挤（或被迫缩小字号） |
| 并列与限定 | 并列的各项同等处理；节选、强调、拆句没有改变原文的范围或限定；整组共有的标签只写一次 |
| 一致性 | 与同类页面的版式、位置、配色一致；没有额外装饰 |

工作台逐页审查时，会在页面旁显示该页的自动指标，作为判断参考。

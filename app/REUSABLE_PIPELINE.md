# 可复用的来源到 PPT 流程

目标是每次导入新材料后重新执行阅读、总结、叙事、分页、构图和视觉复审；第六章课件仅是回归样本，不提供下一份材料的页数、文案或版式。

| 阶段 | 模型的判断 | 程序的硬约束 | 当前状态 |
| --- | --- | --- | --- |
| 全文阅读 | 识别材料论证、块、困难处和覆盖状态 | 来源 SHA、全页/全块覆盖、读取件资格与结构页内容 | 已接入读取件验收；每个新生成任务仍须重新阅读 |
| 章节级全文总结 | 按材料语义写总述和分节总结 | 当前来源身份、每页引用、块号定位、不得用代码拼医疗结论 | 全文简报、导入验收、来源定位和交付依赖已实现；HTTP 自动模型路由待专项资格 |
| 演示叙事和分页 | 结合受众与任务筛选、排序、分配页目标 | Claim/来源不丢失、不静默改写数值或医疗限定 | 已有可审计语义页图和读取件到 PageSpec 的连接 |
| Layout IR | 根据每页目标选构图、层级、分组、焦点与理由 | 只接受合法语义和容量范围；坐标由编译器计算 | 模型与手动提交均可用；结构页无内容会阻断 |
| 渲染 | 选用受支持的写出器生成可编辑对象 | 回读文字、顺序、对象和来源；固定编译计划 | 当前写出器是 Artifact Tool 原生对象路径。PptxGenJS 可作为后续替换写出器，但须先通过同一回读和实物渲染基准 |
| W15 视觉复审 | 看真实 PowerPoint 图片，指出遮挡、拥挤、弱层级和无效留白，迭代 Layout IR | 逐页 PNG、PPTX 字节、计划与素材哈希绑定；有 `REVISE` 不交付 | 自动入口需独立视觉模型；当前 Codex 模型可用渲染包和逐页提交入口。两条路径的真实 PowerPoint 冒烟已通过 |
| W16/交付 | 人复核 RED 临床判断与最终可用性 | 交付使用已复审的同一 PPTX 字节 | 现有人工门与快照机制继续适用 |

`pom` 类 Layout 思想适合作为候选构图的评分和约束，不应负责写医学正文。自有 Layout IR 是语义与写出器之间的稳定接口。精品模板库（包括 pptx-automizer 模板）宜拆成版心、字体、色彩、母版和可复用图形组件，作为 IR 的视觉资源；不能让模板决定哪些事实进入页面。只有通过语义回读、PowerPoint 实物渲染和 W15 逐页复审的写出器或模板，才可进入交付路径。

当前不能宣称“自动总结和自动美化已全部完成”：章节总结的自动 HTTP 模型能力未资格化，独立视觉模型没有生产配置，50 页回归样本仍有密集和重复版式。当前 Codex 模型可通过简报/提交接口参与两步，但它看到的 `PASS` 仍不能替代 W16 人工临床复核。下一步是跨材料能力基准与质量阈值，而非继续修改样本 PPT 来制造一次性的好看结果。
